## recorder — Standalone Data Recorder

**Path**: `apps/recorder/`

Records raw Bybit mainnet WebSocket data to SQLite. Reuses `event_saver` collectors + writers directly.

### Key Rules

- Run via: `uv run recorder --config path/to/config.yaml`
- Fixed UUIDs for DB seeding (stable across restarts); new Run per session
- `Strategy.symbol` VARCHAR(20) — store only first symbol; full list in `config_json["symbols"]`
- All WS handlers use `asyncio.run_coroutine_threadsafe()` — every future gets `_log_future_error()` callback
- `SecretStr` for API credentials — access via `.get_secret_value()`
- Defaults to `testnet=False` (mainnet), unlike gridbot
- Config search: `RECORDER_CONFIG_PATH` env → `conf/recorder.yaml` → `recorder.yaml`
- Lifecycle: `self._running = True` at top of `start()` inside try/except; `stop(error=True)` marks run as "error"
- **Phase 4 shared DB + surgical wipe + identity bootstrap (features 0049 + 0053)**: Phase 4 default is a **shared SQLite DB** used by gridbot, recorder, replay, and comparator. All four processes must resolve `database_url` to the same physical file; the documented form is `sqlite:////<abs-path>/data/recorder_ltcusdt_phase4.db` (four slashes = absolute), avoiding gridbot CWD-dependent relative resolution. `scripts/phase4/start_recorder.sh` no longer parses YAML in shell — it invokes `scripts/phase4/prepare_recorder_session.py` (thin wrapper around `recorder.prepare_session.main`), which uses `recorder.config.load_config` so `database_url` env-var expansion (`${VAR}`) is honored. Prepare does three things in one pass: (1) **§5.1 + §5.2 surgical wipe** inside a single `BEGIN IMMEDIATE` transaction with `PRAGMA foreign_keys=ON` — §5.1 deletes any rows still stamped with the legacy placeholder `account_id='00000000-...-002'` (one-time 0053 migration; idempotent thereafter); §5.2 broad-deletes `private_executions`, `orders`, `wallet_snapshots`, `position_snapshots WHERE source='live'`, then `runs WHERE run_type='recording'`. The final `runs` delete cascades through `position_snapshots.run_id` and removes `source='backtest'` rows tied to the recording runs (intentional — old replay artifacts); it also clears `private_stream_gaps` via its `runs` CASCADE (feature 0110 — no explicit DELETE). `ticker_snapshots` is **not** wiped — public ticker data has no `account_id` column and is reusable across recorder restarts. (2) **Identity bootstrap (when `account:` set)**: insert-if-missing `User`/`BybitAccount`/`Strategy` rows derived from `--gridbot-config` so the recorder's verify-only `_seed_db_records` succeeds on a clean DB without requiring gridbot to start first. No `runs` row is inserted by prepare — gridbot still creates `run_type='live'`, recorder still creates `run_type='recording'`. (3) **Preflight verify**: runs the same `verify_shared_db_parents` (`apps/recorder/src/recorder/shared_db_parents.py`) the recorder uses — 3 existence + 5 metadata checks. Stale rows with mismatched `environment` / `strategy_type` / `symbol` / ownership fail here (`start_recorder.sh` aborts), not after the recorder has been launched into a guaranteed `_seed_db_records` failure. `BybitAccount.environment` is bootstrapped from gridbot `AccountConfig.testnet` (not recorder top-level `testnet`); the recorder/gridbot testnet config-parity check at prepare time guards against further drift. The wipe does **not** delete the DB file or the `-wal` / `-shm` sidecars. Preserved on each recorder start: `grid_state_snapshots` (gridbot-owned, feature 0047 seed data), `runs WHERE run_type='live'`, `bybit_accounts`, `strategies`, `users`, `ticker_snapshots`. If the DB file does not exist yet, the wipe is a no-op; prepare calls `db.create_tables()` before parent inserts. Helper scripts and runbook snippets that need the recorder identifiers must select the **latest `runs.run_type='recording'`** row — never unfiltered `ORDER BY start_ts DESC LIMIT 1` in a shared DB, since the newest row can belong to live gridbot. `ACCOUNT_ID` must come from that same recording-run row, not from `bybit_accounts LIMIT 1` (which can pick the wrong account when shared setup data contains multiple); after 0053 this `ACCOUNT_ID` is the uuid5 `account_id_for(name)` value, not the legacy placeholder. `public_trades` is **not** part of the wipe — Phase 4 LTCUSDT runs with `capture_public_trades: false`. Recorder credentials in Phase 4 configs are `${BYBIT_READONLY_API_KEY}` / `${BYBIT_READONLY_API_SECRET}` (read-only), distinct from gridbot's live `${BYBIT_API_KEY}` / `${BYBIT_API_SECRET}` (trade-permission). Resolved by feature 0052: replay's `grid_state_snapshots` lookup is cross-run by `(account_id, strat_id, symbol)`, so the recorder/gridbot `run_id` divergence no longer drops the DB grid-state seed (see `grid-db.md` → "Grid-state snapshots" for the contract).

- **Phase 4 recorder startup — snapshot sentinels are the shell contract (feature 0055)**: `start_recorder.sh` must classify the initial REST snapshot result via terminal sentinels emitted by `recorder.py` (`_write_initial_rest_snapshot`, and `Recorder.start()` when the collectors fail to start — 0110 B1c-2), not by grepping the human-readable `Initial REST snapshot:` INFO line. The recorder emits the INFO line *before* the WARNING on the zero-count failure path, so a wait loop that breaks on the INFO line races the failure and can declare success on an incomplete snapshot. Sentinels: `RECORDER_SNAPSHOT_OK` (wallet_count > 0 AND position_count > 0 AND no failed position symbol) and `RECORDER_SNAPSHOT_INCOMPLETE` (a collector did not start, auth-client construction failure, zero wallet/position rows, OR a failed position symbol — 0110 B2a: `get_positions` raised, an open row's leg is unknown, or a real row failed conversion; its rows are only placeholders, so counting them made a failed fetch look OK). Two shell libs back this contract — both side-effect-free at top level so pytest can source them: `scripts/phase4/lib/recorder_snapshot_check.sh` (`_classify_recorder_snapshot` returns 0/1/2 for OK/INCOMPLETE/timeout) and `scripts/phase4/lib/recorder_stop.sh` (`_stop_recorder_pattern PATTERN [WAIT_SECONDS]` SIGINTs by `pkill -f`, polls `pgrep -f`, returns 0 on clean shutdown / 1 with a `ps aux` diagnostic on stderr if still alive). On INCOMPLETE or the 60 s timeout (`SNAPSHOT_WAIT_SECONDS`, passed to the classifier for its diagnostic; was 15 s before 0110 B1c-2) the launcher calls `_stop_recorder_pattern "recorder --config $CONFIG"` (pattern, not `$RECORDER_PID` — the `uv` wrapper PID may shadow the Python child), waits up to 10s, and exits non-zero with no `Recorder PID:` tail. Same helper is used for the stop-prior-recorder block at script start, so kill+verify lives in exactly one place. Adding new exit paths in `_write_initial_rest_snapshot` or in the collector part of `Recorder.start()` requires emitting one of the two sentinels — otherwise the wait loop hangs to timeout. The launcher process-management branches (kill on incomplete, kill on timeout, manual-intervention on stuck shutdown) are covered by `apps/recorder/tests/test_start_recorder_check.py:TestStopRecorderPattern` via bash-function stubs (`pkill`/`pgrep`/`sleep`/`ps` defined before sourcing the lib — function lookup wins over PATH). `start_recorder.sh` itself is still not sourced from pytest (top-level side effects); `TestStartRecorderLauncherIntegration` instead asserts the launcher sources the lib and calls the helper.

- **Private-stream gap rows (feature 0110 B1a, lifecycle changed in B1c-1)**: rows are normally opened at disconnect and closed at reconnect (see "Private-stream coverage" below). `_record_private_gap` (one best-effort `pending` row per symbol, already closed; a DB error is logged and recovery still runs) is now only the fallback for a symbol with no open row. `_persist_gap_outcome(gap_id, symbol)` stores the `ExecutionRecoveryResult` when the future completes (cancelled / crashed → `failed`, via `recovery_result_from_future`), through `_try_gap_write` (retried on DB error). Both writes are single-row synchronous ORM calls on the owner loop (deliberate). A test gap must be recent: the collector's gap end is the real reconnect time and a gap older than 7 days is clamped + `failed`.

- **Startup order (feature 0110 B1c-2)**: `start()` = writers → collectors (public, then private; both bounded, both raise `CollectorStartError` for a timeout or any connect error) → private session row → initial REST snapshot → health loop. The REST snapshot runs AFTER the confirmed private session, so its rows lie inside the session (before B1c-2 it ran first). ANY exception in writer init, run seeding or the collectors — a cancellation included — logs `Recorder start aborted: <cause>` and `RECORDER_SNAPSHOT_INCOMPLETE`; a cancelled REST snapshot, or one an exception escapes from, logs the sentinel alone. Either way `start()` re-raises (the sentinel is what the launcher waits for; every exit path must emit one) and `main()` then stops the recorder with `error=True`. `main()` installs SIGINT/SIGTERM handlers BEFORE `start()` (they cancel it and run the error stop; once the start is done they call `Recorder.request_shutdown()`, and they stay installed until `run_until_shutdown` replaces them): a backgrounded `nohup` recorder ignores SIGINT until a handler exists, so without them the launcher could not stop a recorder that is still starting. Side effects of subscribing first: a WS wallet/position/order row from the seconds before the REST snapshot can precede the t=0 row (so replay's seed pre-check is only a coarse guard — see `replay.md`), and a fill during the snapshot's REST calls is both in the REST position row and recorded by WS — seed `at_ts` a few seconds after `RECORDER_SNAPSHOT_OK`, not inside that window.
- **Post-gap REST snapshot (0110 B3)**: `_recover_private_gap` (every gap path: reconnect, late readiness, liveness-only recovery, lost write) ends with `_schedule_post_gap_snapshot()`, which runs `_write_post_gap_snapshot` (fresh auth client; `_snapshot_positions(..., label="Post-gap snapshot", evidence_only=True)` FIRST, then `_snapshot_wallet(..., evidence_only=True)` ONLY if positions were written and no symbol failed (under `evidence_only` every skipped symbol counts as failed, `empty_response` too; `proven` is set only after the USDT row is built) — the wallet seed never moves past a gap without the positions; INFO `Post-gap snapshot: wallet=N coins, positions=M rows`, or a WARNING `wrote nothing` when both are 0). Wallet `evidence_only` writes nothing unless the reading has a USDT `walletBalance` and the account `totalEquity` + `totalAvailableBalance` (an empty field would be coerced to 0 and become the newest seed, which replay's `load_wallet_seed_full` refuses — turning a seedable run unseedable). Why: replay seeds from the latest rows at a window's start and live-check needs gap-free coverage from those rows on; a leg whose size has not changed keeps the startup row as seed (Bybit `updatedTime` only moves on a size change), so without this every later window reached back over the gap and SKIPped. Rules: NO `RECORDER_SNAPSHOT_*` sentinel (launcher startup contract only); `evidence_only` writes NOTHING for a symbol whose fetch failed / was empty / had a malformed or unresolvable open row (a placeholder would become replay's flat seed and live-check's unfit end anchor — worse than keeping the older rows); `absent_side` is still written. At most one snapshot in flight (`_post_gap_snapshot_running`, owned by the coroutine — cleared in its `finally`, in the same loop step as its last rerun check; NOT `future.done()`, which a later loop callback sets, so a gap in that window was lost); a gap closing meanwhile sets `_post_gap_snapshot_again` for exactly one more run so the last snapshot postdates the last gap; all of it runs on the event loop (gap paths are loop callbacks); `stop()` cancels it (never awaited); `start()` resets the state. Positions + wallet only: open orders are NOT re-snapshotted (REST lists only open orders, so orders filled/cancelled during a gap would stay "active" — whole-order reconciliation is #274).
- **Synthetic position zero-rows are marked (0110 B2a)**: `_snapshot_positions` always writes Buy + Sell per symbol; a row it synthesises (size 0, NULL telemetry) carries `raw_json={"synthetic": "rest_failure" | "malformed" | "absent_side" | "empty_response"}` — `get_positions` raised; the real row failed conversion or an open row's leg is unknown; the successful response had rows for the symbol but not this leg; or it had no row for the symbol at all (wrong `category`/`settleCoin` scope, key permissions, or never traded — WARNING, not INCOMPLETE). A real row keeps Bybit's payload; a flat hedge leg REST returns with `side=""` is a real row, its side from `positionIdx` via `event_saver.writers.leg_side`. `absent_side` comes from a successful fetch, so it is a known flat leg; `rest_failure` / `malformed` are not (B2c's anchor-fitness check treats them as unfit); B2c decides how to treat `empty_response`. A row for the symbol whose leg `leg_side` cannot resolve is skipped: a flat one (one-way mode) is logged at INFO and the legs stay `absent_side`; an open one is logged at WARNING, both synthesised legs become `malformed` and the symbol counts as failed. `_snapshot_positions` returns `(rows, failed_symbols)`; any failed symbol makes the snapshot INCOMPLETE (see sentinels above). No application code reads position `raw_json` (snapshot `raw_json` readers are wallet-only: replay's collateral path in `snapshot_loader.py` and live-check's `shared_wallet.py`); the one exception is the research script `scripts/research_0045_im_mm_distribution.py` (`_leverage_from_raw`), which falls back to leverage 1 on a synthetic row.

- **Private-stream coverage (feature 0110 B1c-1)**:
  - **Gap rows open before the reset.** The collector's `on_disconnect` → `_handle_private_disconnect` opens one row per symbol (`gap_end=NULL`) in one transaction and keeps the ids in `_open_gap_ids` only after commit. DB errors propagate, which skips the reset — for at most `_MAX_OPEN_GAP_FAILURES − 1` (2) probes in a row. On the 3rd consecutive failure it returns normally so the socket is reset anyway (orders, positions and wallet have no REST backfill); the gap is then recorded at reconnect by `_record_private_gap`. `_handle_private_gap` closes the open rows and forgets each id at once, even if the close write fails — each outage owns its row, so a queued close can never be replayed onto a later outage. A symbol with no open row (late readiness) gets a closed row from `_record_private_gap`.
  - **Failed gap writes** (close, outcome, or the fallback row insert) go to `_pending_gap_writes`. They are retried on every checkpoint attempt (before its early returns) and on every private gap, since the checkpoint does not run while the socket is degraded. `grid_db.RowNotFoundError` is dropped; any other `ValueError` is retried. The first failure logs a traceback, retries one WARNING line.
  - **Checkpoint barrier.** `_private_checkpoint` is the collector's `on_healthy_probe`. Execution/order/position/wallet handlers must submit through `_submit_private`, which creates and registers the future under `_pending_lock`. The barrier copies those futures under the same lock, awaits them and flushes the 4 writers. It publishes `barrier_ts − LIVENESS_MARGIN` only if no write failed, no gap write is queued and no gap row is open (`_open_gap_ids` empty). A new private handler that bypasses `_submit_private` would let the checkpoint certify writes it never waited for.
  - **A failed or cancelled private write** sets `_private_write_lost` under `_pending_lock` (blocks the checkpoint) and schedules `_record_lost_write_gap` on the loop: a gap starting at `earliest loss − LIVENESS_MARGIN` is recorded (REST recovery included) and the latch is released (`_private_write_lost_at` keeps the earliest unrecorded loss time, since the callback can run late). See "Lost write vs open gap" below for what is recorded when an outage gap is open. If a needed gap cannot be recorded (recorder stopping) the latch and the loss time stay set. The checkpoint awaits pending writes through `asyncio.shield`, so a cancelled checkpoint never cancels a write.
  - **Restart.** `start()` clears the coverage state (`_pending_futures`, write-lost latch, session id, `_open_gap_ids`, `_pending_gap_writes`): `stop()` → `start()` is a new run.
  - **Session row.** It is written right after `PrivateCollector.start()`, which only returns on a confirmed ready socket (best-effort; none → no checkpoint).
  - **Lost write vs open gap.** `_record_lost_write_gap` records `[loss − margin, open gap start]` as its own closed row when the loss is older than the open outage gap (`_open_gap_start`), nothing when it lies inside it. It goes through `_recover_private_gap(..., close_open=False)`, which never touches open rows; only the collector's `_handle_private_gap` (reconnect) closes them and resets `_open_gap_failures`. Open-gap write failures past the limit log one WARNING each with the running count.
  - **Known limit.** Events dropped before they reach a writer's buffer (collector normalizer / callback errors, an order with no `run_id`) are logged but invisible to the checkpoint.
  - **Health line.** `Health:` stats carry `private_ws.degraded`.
  - **Tests** backdate the session (`_backdate_session` in `test_recorder_gap_reconciliation.py`), because a checkpoint 75 s back cannot pass a fresh `connected_at`.

### Recorder-specific test pitfalls

1. **TickerEvent fields**: Does NOT have `index_price` or `next_funding_time` — check `gridcore.events.TickerEvent` dataclass definition before constructing test fixtures.
2. **Mock collectors need `stop = AsyncMock()`**: When mocking `PublicCollector`/`PrivateCollector`, must set `stop` as `AsyncMock()` since `Recorder.stop()` awaits them.
3. **`_close_dangling_coro()` pattern**: When testing `cli()` that calls `asyncio.run(main(...))`, the mock creates an unawaited coroutine. Use the helper to close it after assertions (same pattern as gridbot `test_main.py`).
4. **Position/wallet test data format**: `PositionWriter` and `WalletWriter` expect Bybit-formatted dicts with `"data"` keys (e.g., `{"data": [{"symbol": "BTCUSDT", ...}]}`). Flat dicts silently produce zero snapshots.
5. **Test fixture deduplication**: Shared `db` fixture lives in `conftest.py` — do not duplicate in individual test files. Same for `basic_config` and `config_with_account`.
6. **Mock config completeness**: When using `MagicMock()` for config in tests, set all attributes that `main()` accesses before the code path under test. E.g., `mock_config.database_url = "sqlite:///test.db"` — bare MagicMock attributes break `urlparse()`.
7. **Vertical gap tests** live in `test_recorder_gap_reconciliation.py`. Do not mock the collectors. Patch `event_saver.collectors.public_collector.PublicWebSocketClient`, `event_saver.collectors.private_collector.PrivateWebSocketClient`, **and both** `recorder.recorder.BybitRestClient` and `event_saver.reconciler.BybitRestClient`.
8. **Vertical gap test triggers / assertions**: private trigger is `PrivateCollector._ws_health_check_once` on a dead fake socket (0037), not 30s silence (0035). Public REST id field is `execId`. Drain fire-and-forget reconcile by polling DB rows, not by reading `_gap_count` alone.
