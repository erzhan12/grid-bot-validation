# Feature 0107 — Recorder disconnect/reconnect/reconciliation integration tests

Issue: [#211](https://github.com/erzhan12/grid-bot-validation/issues/211) (body updated 2026-09-23)

> **For agentic workers:** test-only feature. Write the tests first. They should pass against current production. If a test fails, stop and diagnose — do not change production to paper over a bad fixture. Do not commit unless the user asks.

**Goal:** Replace the skipped `TestRecorderDisconnectReconciliation` stub with hermetic recorder-level tests that drive a collector disconnect into real `GapReconciler` writes and assert persisted SQLite rows.

**Architecture:** Keep production code unchanged. Start a real `Recorder` with real `PublicCollector` / `PrivateCollector` / `GapReconciler` against the in-memory `db` fixture. Substitute only the network edges: fake WS clients (so `connect()` never hits Bybit) and a fake `BybitRestClient` that returns canned public trades / private executions. Public gaps are fired through the WS `on_reconnect` callback the collector registered at `start()`. Private gaps are fired through `PrivateCollector._ws_health_check_once()` after marking the fake socket dead — not through 30s of silence (0035 disabled that watchdog; 0037 is the live private trigger).

**Tech Stack:** pytest + pytest-asyncio, `unittest.mock.patch`, existing `apps/recorder/tests/conftest.py` fixtures, in-memory SQLite.

**Spec:** GitHub issue 211 (updated body) and this plan.

## Global Constraints

- Hermetic: no real Bybit, no real sockets.
- Do not mock `PublicCollector`, `PrivateCollector`, `GapReconciler`, or `Recorder._handle_*_gap`.
- Do not add production hooks, config flags, or a shorter health-check interval just for tests.
- Do not implement `test_reconciliation_failure_marks_run_or_health_unhealthy` — failed reconcile only logs via `_log_future_error` and increments `_gap_count`.
- Do not re-test collector-only or reconciler-only behavior already covered in `apps/event_saver/tests/`.
- `make test` / `uv run pytest apps/recorder` still passes.
- No commit unless asked.

## Review Focus

- Fake REST must satisfy **both** snapshot start and gap backfill, or `Recorder.start()` with an account will raise / hang the test before the gap is ever fired.
- `BybitRestClient` is imported in two places; patching only `recorder.recorder.BybitRestClient` leaves `reconcile_executions` constructing a real client.
- Public REST trade id field is `execId` (not `tradeId`); private executions must be `category=linear` and `execType=Trade` or `_executions_to_models` drops them.
- `_handle_*_gap` schedules work with `run_coroutine_threadsafe`; asserting `_gap_count` alone does not prove a DB write. Drain the loop and wait for rows.
- `Recorder.stop()` must run in `try/finally` — real writers start flush loops.

## Why a new file

`test_recorder.py` already mocks collectors at the class/method level and is ~935 lines. Recorder tests are already split by concern (`test_health.py`, `test_initial_rest_snapshot.py`). The vertical path needs the opposite of those mocks (real collectors) and would fight the existing `@patch("recorder.recorder.PublicCollector")` style if stuffed into the same classes.

## Fakes

### Fake public WS

Patch `event_saver.collectors.public_collector.PublicWebSocketClient` (the collector's import site).

Constructor must accept and store the kwargs `PublicCollector.start()` passes: `symbols`, `testnet`, `on_ticker`, `on_trade`, `on_disconnect`, `on_reconnect`. `connect()` / `disconnect()` are no-ops. `get_connection_state()` returns `None`. Expose `fire_reconnect(disconnected_at, reconnected_at)` that calls the stored `on_reconnect`. After `Recorder.start()`, the instance is `recorder._public_collector._ws_client`.

### Fake private WS

Patch `event_saver.collectors.private_collector.PrivateWebSocketClient`.

Constructor stores `on_disconnect`, `on_reconnect`, and the other kwargs `PrivateCollector.start()` passes. `connect()` / `disconnect()` are no-ops. `is_socket_alive()` returns a mutable `alive` flag, default `True` so start + the first health-loop tick do nothing. `reset()` sets `alive = True`. `get_connection_state()` returns a `ConnectionState` with `last_message_ts` set to the intended gap start (so `_ws_health_check_once` uses that timestamp, not `datetime.now()`).

Do **not** wait for `_PRIVATE_WS_HEALTH_CHECK_INTERVAL` (10s). After start, set `alive = False` and `await recorder._private_collector._ws_health_check_once()`. That is the production method 0037 added; the timer is already tested in `test_private_collector.py`.

`reset()` must return immediately. The health check wraps it in `_run_in_daemon_thread` + `wait_for`; a hanging `reset` fails the test on the 30s timeout.

### Fake REST

`Recorder.start()` constructs `BybitRestClient` via `recorder.recorder.BybitRestClient` (public reconciler client + 0029 snapshot). `GapReconciler.reconcile_executions` constructs a **second** client via `event_saver.reconciler.BybitRestClient`. Patch both names to the same fake class / factory.

Required methods:

- `get_recent_trades(symbol, limit=1000)` → list of dicts (`execId`, `time` ms, `side`, `price`, `size`). Used by `reconcile_public_trades`.
- `get_executions_all(symbol, start_time, end_time, max_pages, return_truncated=True)` → `(list[dict], truncated: bool)`. Used by `reconcile_executions`. A bare list will blow up the `executions_data, truncated = ...` unpack.
- Snapshot methods so account-mode `start()` does not raise: `get_wallet_balance`, `get_positions`, `get_open_orders`. Empty / `{"list": []}` is fine; start logs `RECORDER_SNAPSHOT_INCOMPLETE` and continues.

Keep a call counter on `get_recent_trades` / `get_executions_all` so the below-threshold test can assert REST was not called.

### Payload shapes (copy these keys)

Public trade (maps through `_trades_to_models`; id field is `execId`):

```
{"execId": "gap-trade-1", "time": <ms inside gap>, "side": "Buy", "price": "50000.00", "size": "0.001"}
```

`time` must fall inside the reconciler window: `[gap_start - 1s, gap_end + 1s]` (the ±1s buffer in `reconcile_public_trades`). Put it in the middle of the gap.

Private execution (maps through `_executions_to_models`; dropped unless both filters match):

```
{"category": "linear", "execType": "Trade", "execId": "gap-exec-1", "orderId": "ord-1",
 "orderLinkId": "link-1", "symbol": "BTCUSDT", "side": "Buy",
 "execPrice": "50000.00", "execQty": "0.001", "execFee": "0.01", "closedPnl": "0",
 "execTime": <ms inside [gap_start, gap_end]>}
```

Private has **no** ±1s buffer. `execTime` outside `[reconcile_start, gap_end]` is not filtered by the reconciler (it asks REST for that window), but keep it inside so a future filter cannot vacuous-pass the test.

### Config / identity

- Public tests: `config_with_trades_enabled` + `db`. Public backfill writes `PublicTrade` via the repository even when `capture_public_trades` is False, but this fixture is the public-trade-recording config and matches the stream under test. Leave `gap_threshold_seconds` at default `5.0`. Use a 30s gap to reconcile, a 1s gap for below-threshold.
- Private tests: `config_with_account` + `db` + `db_with_gridbot_seed` (same pair as existing account-mode tests). Without the seed, `_seed_db_records` fails the Run FK insert.

### Waiting for fire-and-forget writes

`_handle_public_gap` / `_handle_private_gap` increment `_gap_count` synchronously, then schedule `reconcile_*` with `asyncio.run_coroutine_threadsafe` on `self._event_loop`. The test does not get that `Future`.

Helper in the new file (do not import `await_future` from `test_recorder.py` — that helper requires the Future handle):

1. Assert `_gap_count` advanced (proves the collector reached the recorder handler).
2. Poll the DB on the event loop with a short `asyncio.sleep(0.01)` until the expected row count appears, timeout ~2s, then `pytest.fail` with the last count. Do not use a single `asyncio.sleep(N)`.

For the below-threshold case, `_gap_count` still increments (handlers count unconditionally) but REST is not called and no rows appear. Yield once so a mistakenly-scheduled reconcile would have a chance to run, then assert REST call count is 0 and row count is 0.

## Tests

One class, `TestRecorderDisconnectReconciliation` (same name as the deleted stub).

### `test_public_ws_disconnect_triggers_gap_reconciliation`

1. Patch public WS + both REST import sites. REST `get_recent_trades` returns one in-gap trade.
2. `Recorder(config_with_trades_enabled, db).start()`.
3. `recorder._public_collector._ws_client.fire_reconnect(gap_start, gap_end)` with a 30s window.
4. Wait until `PublicTrade` row count is 1.
5. Assert `trade_id == "gap-trade-1"`, `symbol == "BTCUSDT"`, `price == Decimal("50000.00")`, `_gap_count == 1`.
6. `stop()` in `finally`.

This is the vertical public path: WS callback → `PublicCollector._handle_reconnect` → `Recorder._handle_public_gap` → `GapReconciler.reconcile_public_trades` → `PublicTradeRepository.bulk_insert`.

### `test_private_ws_disconnect_triggers_gap_reconciliation`

1. Patch public WS (start always constructs it), private WS, both REST import sites. `get_executions_all` returns `([one in-gap linear Trade], False)`.
2. `Recorder(config_with_account, db).start()` with `db_with_gridbot_seed`.
3. Set fake private `alive = False`. `get_connection_state().last_message_ts` is `gap_start` at least 30s in the past so `now - gap_start >= 5s`.
4. `await recorder._private_collector._ws_health_check_once()`.
5. Wait until `PrivateExecution` row count is 1.
6. Assert `exec_id == "gap-exec-1"`, `symbol == "BTCUSDT"`, `run_id == str(recorder._run_id)`, `_gap_count == 1`.
7. `stop()` in `finally`.

This is the vertical private path: TCP probe → `reset` → `_handle_reconnect` → `Recorder._handle_private_gap` → `GapReconciler.reconcile_executions` → `PrivateExecutionRepository.bulk_insert`.

Do not simulate 30s of message silence. Do not re-enable `message_gap_watchdog_enabled`.

### `test_reconnect_below_threshold_does_not_write`

Public path. Same setup as the first test, but `gap_end - gap_start == 1s` (default threshold 5s). After `fire_reconnect` and one loop yield: `get_recent_trades` call count is 0, `PublicTrade` count is 0, `_gap_count == 1` (count is unconditional; backfill is not).

### `test_reconnect_does_not_duplicate_already_persisted_events`

Public path. Before firing a 30s reconnect, insert one `PublicTrade` with `trade_id="gap-trade-1"` (same `execId` REST will return). After wait: `PublicTrade` count is still 1. Relies on `PublicTradeRepository.bulk_insert` `ON CONFLICT DO NOTHING` on `trade_id` — the production dedup the issue asked to pin at recorder level.
