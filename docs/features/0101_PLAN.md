# Feature 0101 — Subtract seed-time unrealized PnL (U0) from replay balance/equity baselines

GitHub issue: **#244**. Feature branch: `feature/0101-u0-seed-double-count`.

## Context

When a replay run is **seeded** (`seed.enabled=true` — the mode `live_check`
uses, and any seeded parity replay), the session balance baselines are taken
verbatim from the recorded Bybit UTA wallet snapshot at `seed.at_ts`:

- `initial_balance ← WalletSeed.total_available_balance`
  (`apps/replay/src/replay/engine.py:448-452`)
- `initial_equity ← WalletSeed.total_equity`
  (`apps/replay/src/replay/engine.py:456-460`)
- shared-wallet path: `MultiReplayEngine._build_shared_session`
  (`apps/replay/src/replay/multi_engine.py` ~572-594) — `initial_balance ←
  wallet_seed.total_available_balance`, `initial_equity ←
  wallet_seed.coin_balance`. **Important asymmetry:** `coin_balance` is the
  per-coin USDT `walletBalance` — CASH, which does **not** include perp UPL
  (coin-level `equity = walletBalance + UPL`; the 0095 tests lock the
  cash+one-U contract in `apps/replay/tests/test_multi_engine.py:211-229`).
  So on the multi path only `initial_balance` (TAB) is overstated by `U0`;
  `initial_equity` is NOT. **Subtract `U0` from `initial_balance` ONLY**
  there — subtracting it from `coin_balance` would invert the bug
  (understate equity by `U0`). The `coin_balance`-vs-`total_equity`
  divergence itself stays out of scope.

Both Bybit UTA fields **already include** the unrealized PnL of positions open
at snapshot time (call it `U0`):
`totalEquity = totalWalletBalance + totalPerpUPL`;
`totalAvailableBalance = totalMarginBalance − totalInitialMargin`, and
`totalMarginBalance` includes UPL.

The session then evolves both baselines per tick via
`BacktestSession._pnl_delta` (`apps/backtest/src/backtest/session.py:260-276`),
applied in `refresh_balances` (`session.py` ~359-366) and `update_equity`
(`session.py` ~393-396):

```
pnl_delta       = total_realized + pending + unrealized_pnl(t) − commission + funding
current_balance = initial_balance + pnl_delta
total_equity    = initial_equity + pnl_delta + collateral_remark_delta
```

`unrealized_pnl(t)` is the **FULL** current unrealized of the seeded trackers,
not the increment `U(t) − U0`. Correct Bybit evolution is:

```
totalEquity(t) = E0 − U0 + realized + U(t) − fees + funding
```

Our model computes `E0 + realized + U(t) − fees + funding` → **both baselines
are overstated by the constant `U0` for the whole run** (understated when
`U0 < 0`). The bug is acknowledged in `docs/features/0042_PLAN.md:90-97`
(~0.35 USDT liq impact, accepted then); feature 0043 later made `total_equity`
the pair-liquidation pool input, magnifying the blast radius.

**Blast radius:** `total_equity` feeds the 0043 hedge-aware pair-liquidation
formula (`liq_price_*` parity metrics); `current_balance` feeds order margin
gating, wallet-fraction qty sizing (`amount: "x..."`, live config uses
x0.0005), margin-ratio logging, and risk-multiplier state. **NOT affected:**
the `live_check` **single-strat** verdict formula (compares
realized/commission/unrealised sums + qty, no balances; the `--shared` mode
DOES gate `equity_ok` on `total_equity` — `apps/live_check/.../verdict.py:207`
— but that reads the multi equity axis, which this fix leaves untouched) —
all historical 0100 PASS results remain valid as statements about pre-fix
code; the 0065 collateral re-mark term is a separate
additive delta and is also unaffected. **Indirectly affected going forward:**
the corrected `current_balance` feeds wallet-fraction qty sizing and margin
gating inside the replay, so post-fix seeded replays can place slightly
different orders and live_check verdicts must be re-confirmed empirically —
the empirical-validation step below therefore includes a post-fix
`make live-check` PASS on both strats, not just the equity-gap diag.

## The fix

Compute `U0` at seed time from the **recorded position snapshot rows** and
subtract it from the overstated baselines before the `BacktestSession` is
constructed (single engine: BOTH baselines; multi engine: `initial_balance`
only — see Context).

**`U0` source hierarchy (per seeded leg, in order):**

1. **Primary — recorded `unrealised_pnl`.** `PositionSnapshot` stores Bybit's
   own `unrealisedPnl` (`shared/db/src/grid_db/models.py:388`, nullable) —
   mark-based, computed by Bybit itself, self-consistent with the same row the
   seed's `size`/`entry_price` come from. `U0 = Σ legs' unrealised_pnl`. This
   sidesteps re-deriving UPL from a separately-selected ticker row (the wallet
   row, position rows, and ticker rows are all independently selected
   at-or-before `at_ts` and may carry slightly different timestamps —
   re-derivation would introduce, not remove, misalignment).
2. **Fallback — row-local mark formula.** If a leg's `unrealised_pnl` is
   `NULL` (pre-0059 recordings), use the same row's `mark_price`
   (`models.py:393`, nullable):
   `long → (mark_price − entry_price) × size`,
   `short → (entry_price − mark_price) × size`.
3. **Fail-loud.** A leg with `size > 0` but BOTH fields `NULL` — or
   `size > 0` with `entry_price <= 0` (corrupt seed; checked on BOTH paths,
   because even with a recorded UPL the seeded tracker computes `U(t)` from
   that entry every tick, `position_tracker.py:282`) — raises
   `SeedDataQualityError`. Silently skipping (contributing 0) would knowingly
   preserve the double-count while logging only a WARNING; refusing to seed
   matches the existing corrupt-run behavior in the loader
   (`snapshot_loader.py:522-529`).

- Flat legs (`size == 0`) contribute `0`. No positions at seed → `U0 = 0` →
  **byte-identical** behavior (proven by test).
- **Documented decision:** `compute_seed_upl` runs only when
  `wallet_seed is not None`. On the wallet-fallback path
  (`config.initial_balance`) there is no embedded UPL to subtract, so the
  helper — and with it the `entry_price <= 0` guard — is deliberately NOT
  invoked there; corrupt-entry seeding without a wallet seed is pre-existing
  behavior and out of this feature's blast radius (surgical-change rule).
- Decimal-only math; never `float`.
- No new DB queries and no ticker-repo lookup: the loader
  (**`load_position_snapshots`** — the real function name, exported in the
  module `__all__` at `snapshot_loader.py:911`; construct sites ~531-555)
  already holds `buy_snap`/`sell_snap` — it only needs to pass
  `unrealised_pnl` and `mark_price` through to `PositionStateSeed`. Edit that
  constructor call; do NOT add a parallel function. Timezone handling is
  therefore unchanged (no new `at_ts` comparisons anywhere).

**Basis note (documented residual):** `U0` is mark-price-based (Bybit's
embedding in `totalEquity`/TAB), while the session's per-tick
`unrealized_pnl(t)` is `last_price`-based (`engine.py:635-638`). The
mark-vs-last jitter is a pre-existing, model-wide property (see the benign
`pos_value` mark-jitter precedent) and is NOT changed by this feature; the
subtraction removes the constant `U0` offset, which dominates.

**Carrier:** extend `PositionStateSeed` (frozen dataclass,
`snapshot_loader.py:128-149`) with two new optional fields
`unrealised_pnl: Decimal | None = None` and
`mark_price: Decimal | None = None` — defaults keep every existing
constructor/test valid (same pattern as `cum_realised_pnl`). `WalletSeed`
stays untouched; `U0` is derived from the position seeds already returned at
the engine assignment site, so **subtract at the engine assignment site** —
no `dataclasses.replace` on `WalletSeed` (contrast 0065).

### Shared source of the `U0` computation

Add one helper (no DB I/O — it only reads the seed dataclasses) so both
engines and the tests use identical arithmetic. Put it in
`apps/replay/src/replay/snapshot_loader.py` (co-located with the seed
dataclasses):

```
def compute_seed_upl(
    legs: Iterable[PositionStateSeed | None],
) -> Decimal
```

The single engine passes `[long_seed, short_seed]`; the multi engine passes
all strategies' legs flattened (they share one session, so `U0` sums across
strategies). Per leg:

- `None` or `size == 0` → contributes `0`.
- `size > 0` with `entry_price <= 0` → raise `SeedDataQualityError`
  (corrupt non-flat seed; guarded on BOTH source paths).
- `unrealised_pnl is not None` → contributes `unrealised_pnl` (**takes
  precedence** over the mark formula when both fields are present).
- else `mark_price is not None` → `long → (mark_price − entry_price) × size`,
  `short → (entry_price − mark_price) × size`.
- else (`size > 0`, both fields `NULL`) → raise `SeedDataQualityError`
  (pre-0059 recording without UPL telemetry cannot be seeded correctly;
  silently contributing 0 would preserve the double-count).

Return the Decimal sum. Full type hints + Google-style docstring. The helper
itself logs one INFO line per non-flat leg (direction, size, source used,
contribution) — logging inside keeps the source-hierarchy knowledge in one
place instead of duplicating it at both engine call sites; "no DB I/O" ≠
"no logging".

## Non-obvious constraints (must hold)
- **No new `at_ts` DB comparisons** — the recorded-UPL design adds zero new
  timestamp-bound queries, so no new naive-UTC risk surface. (For reference:
  `get_mark_at_or_before` does NOT tz-normalize its bind — raw
  `exchange_ts <= at_ts` at `shared/db/.../market_data.py:181-190` — one
  reason the ticker-lookup design was rejected. If any future step adds an
  `at_ts` query, bind via `_to_naive_utc` from `replay/engine.py`, 0100.)
- **Decimal-only** money math; never `float`.
- **Multi-path asymmetry is load-bearing**: subtract `U0` from
  `initial_balance` only; `initial_equity` (`coin_balance`, cash) must stay
  untouched or the fix inverts the bug on the equity axis (0095 cash+one-U
  contract, `test_multi_engine.py:211-229`).
- **Do NOT** touch the `live_check` verdict thresholds or the 0100 qty gate —
  orthogonal.
- **Do NOT** re-derive the 0043/0045 liq/IM/MM formulas — only the pool-input
  baseline changes.
- **Do NOT** change the multi-engine `coin_balance`-vs-`total_equity` baseline
  divergence — out of scope; only subtract `U0` from whatever is assigned.
- The recorder DB `data/recorder_ltcusdt_phase4.db` is **LIVE mainnet**; open
  strictly read-only (`mode=ro`) for any empirical step (recorder process is
  running, log `/tmp/recorder.log`).

## Implementation order (TDD)

Work strictly **red → green → refactor**. Write each failing test FIRST, then
the minimal production change to pass it, then refactor while green. Do **not**
implement the fix and add tests afterward.

Reproducing tests live in a new class in
`apps/replay/tests/test_engine_seed.py` (extend the existing seeded-DB
fixtures; set `unrealised_pnl` — or NULL it and set `mark_price ≠ entry` for
the fallback path — on the seeded `PositionSnapshot` rows so `U0 ≠ 0`).
Follow the 0100 **literal-lock** precedent
(`apps/backtest/tests/test_runner.py` `TestEstimatePairImMm`): compute every
expected value **by hand in a comment** and assert the literal — never
recompute the expectation with the session formulas under test.

**CRITICAL — exercise the production wiring.** The existing pipeline test
(`test_engine_seed.py:233-295`) builds its own `BacktestSession` by hand and
never calls `run()` — a test copied from it can go GREEN without the
`engine.py` fix ever wiring in. Cycles 1, 3, 4 must drive the baselines
through production `run()` (with a minimal in-memory tick series), or through
a small session-builder helper **extracted from `run()` and called by it** —
never through a hand-mirrored session construction. Note the current pipeline
test also passes only `initial_balance` (line 290, no `initial_equity`), so
"existing assertion on `total_equity == wallet_seed.total_equity`" does NOT
exist today — don't assume it.

**Cycle 1 — reproduce the overstatement (RED first).**
1. New test `test_seed_upl_overstates_equity_pre_fix` (or the post-fix
   assertion form): seed a **long-only** position with recorded
   `unrealised_pnl ≠ 0`. Drive through production `run()` / extracted
   builder, read `session.initial_equity` / `session.initial_balance`, and
   assert they equal `wallet_seed.total_equity − U0` /
   `total_available_balance − U0` with the hand-computed literal `U0`. RED
   before the fix.
2. Minimal production change in `engine.py`: compute `U0` and subtract. GREEN.

**Cycle 2 — hedge both legs + negative `U0`.**
3. Test `test_seed_upl_hedge_both_legs`: seed long AND short with recorded
   per-leg `unrealised_pnl` of opposite signs; assert baselines reduced by
   the hand-summed net `U0`. Add a **negative net `U0`** case (losing seed):
   subtraction must INCREASE both baselines — literal-locked. **Drive these
   through production `run()` / the extracted builder too** (Cycle 1 is
   long-only; a production path that subtracted only `[long_seed]` must not
   pass this cycle).

**Cycle 3 — evolution → close (equity trajectory).**
4. Test `test_seed_upl_evolution_to_close`: seed a position with `U0 ≠ 0`,
   run ticks that fully close it via the tick series, and assert final
   `session.total_equity` equals a **hand-derived** Bybit-semantics literal
   (`E0 − U0 + realized + U(end) − fees + funding`), NOT a value recomputed
   with `_pnl_delta`. Mechanics that make the literal derivable:
   - `enable_funding=False`; **`wind_down_mode: leave_open`** (CLOSE_ALL
     winds down without a final `update_equity` — 0065 pitfall — so close
     via the tick series and let the last tick's `update_equity` land).
   - `U(t)` in the literal is **`last_price`-based** (`engine.py:635-638`
     feeds `calculate_unrealized_pnl(tick.last_price)`), not mark-based.
   - `realized` in the literal is the **session-window**
     `total_realized_pnl` (starts at 0); the seeded `cum_realised_pnl` is
     already inside `E0` and must NOT enter the literal.
   - **Seed NO working orders** in this test's fixture (the existing
     `seeded_db` fixture restores an open `Buy` at
     `test_engine_seed.py:140-155`). Beware: `execute_tick` runs a live
     hedge-mode grid, and a short-OPEN Sell can sit at the same price as the
     long-close Sell (`_should_place_close` only gates reduce-only) — a
     closing tick can simultaneously open the opposite leg, making the
     "flat" literal false-green while a short is open. The guard is the
     assert: read the runner from the new `ReplayResult.runner` field and
     **assert BOTH tracker sizes are 0** before locking the final
     `session.total_equity` literal; if contamination trips it, adjust the
     grid params / tick series until genuinely flat.
   - Intermediate `total_equity` is not recorded anywhere
     (`equity_curve` is balance-based), so cover the nonzero-`U(t)`
     evolution term with a **split-window second `run()`**: same seed, tick
     series ending while the position is still open (`U(end) ≠ 0`), assert
     that run's final `result.session.total_equity` literal. A full-close
     literal alone (`U(end) = 0`) would leave the evolution term untested.
   This is the test the 0043 same-instant calibration could not catch.
