# Feature 0108: Explicit `contents: read` permission for risk-tier monitor

Issue #213 is a low-severity GitHub Actions hygiene change. The public repository currently checks out successfully, and the issue reports that the last five scheduled runs were green. However, the job-level `permissions` block makes unspecified scopes default to `none`, so the workflow would lose checkout access if the repository became private.

The `check-tier-drift` job must declare exactly `{contents: read, issues: write}`. This is not a failing-CI fix.

## Repository findings

- `.github/workflows/risk-tier-monitor.yml:10-15` defines job `check-tier-drift`, grants only `issues: write`, and checks out the repository with `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`.
- `.github/workflows/ci.yml:25-26` declares workflow-level `contents: read`.
- `.github/workflows/claude.yml:21-26` includes job-level `contents: read` with its other required scopes.
- No existing test owns repository workflow-permission hygiene.
- `Makefile` discovers `tests/integration/` through its `test` target, so no Makefile change is needed.
- PyYAML is already available in the root test venv through the `gridbot` workspace member (`apps/gridbot/pyproject.toml`, pulled in by the root `dev` group). No dependency or lockfile change is needed.

## Files

Create:

- `tests/integration/test_risk_tier_monitor_workflow.py`
  - Add one focused test, `test_check_tier_drift_has_exact_permissions`, that parses the workflow with `yaml.safe_load`.
  - Resolve the repository root from the test file path, select `jobs["check-tier-drift"]["permissions"]`, and assert exact equality with `{contents: read, issues: write}`. Exact mapping equality ensures both scopes are present and rejects additional permissions.

Modify:

- `.github/workflows/risk-tier-monitor.yml`
  - Add `contents: read` to the existing job-level permissions block before `issues: write`.

Do not modify:

- `Makefile`, dependency files, or `uv.lock`.
- `scripts/check_tier_drift.py`.
- The cron schedule, `workflow_dispatch` trigger, issue-filing JavaScript, or any job step.
- The checkout action SHA or its `v7.0.1` comment.
- Any permission beyond `contents: read` and `issues: write`.
