# 0111: Flat hedge leg in the gridbot position cache

Implement issue #292, "[P1] gridbot keeps a closed hedge leg's stale position: WS cache skips side=\"\" rows". Found in the PR #288 review; recorded until now as a "Known hazard" in `.claude/rules/gridbot.md`.

Plan debated 2026-10-04 with codex gpt-6-astra (high), two rounds; every claim below was verified against the checkout by both sides.

## Problem

Bybit reports a hedge leg that closed to flat with `side=""` — on the private WS `position` topic and on REST `/v5/position/list` alike (docs: `return an empty string "" for an empty position`; the WS stream example carries `positionIdx=2, side="", size="0"`). The leg is still identified by `positionIdx` (1 = long, 2 = short). pybit and `bybit_adapter.ws_client._handle_position` forward the frame unchanged.

`PositionFetcher.on_position_message` (`apps/gridbot/src/gridbot/position_fetcher.py:215`) skips rows with an empty side, so `_position_ws_data[account][symbol][side]` keeps the **last non-zero dict** for that leg. Nothing repairs a populated slot: `_fetch_one_account` (`:606-623`) calls REST only when a slot is `None`, there is no invalidation, and the rotation tick reuses the same path. Reproduced in-memory: `size="2"` then `side="", size="0"` leaves the cache and the next `runner.on_position_update` at `2`, with zero WS callbacks and zero REST calls.

The recorder was fixed in 0110 B2a (`event_saver.writers.leg_side`); gridbot was not. No recorded flat-leg payload exists (position recording ended 2026-09-02, before any live leg went flat), so the contract is documentation-derived.

## Impact (verified)

| Consumer | Source of truth | Effect of the stale dict |
|---|---|---|
| `_long/_short_position_value` → C1 `max_notional_per_symbol` (`runner.py:1125`, `:2360`) | ungated `long_state` | over-blocks opens until the leg reopens |
| `position_ratio`, risk multipliers, stored `liquidation_price` (`runner.py:1150-1218`) | ungated `long_state` | mis-sizes opens and opposite-leg closes; no time bound |
| `_is_good_to_place` reduce-only guard (`runner.py:2311`) | 0064-gated size mirror | one 110017 per ghost close → dirty REST refresh by `positionIdx` reads 0 → gate holds 0; permanent dirty + mismatch WARNING streak. Bound fails if the refresh fails (`:1587`, mirror kept) or a forced reconcile clears dirty (`:1630`, ghost overwrites again) |
| C3 `_evaluate_loss_breaker` → `_cur_realized_pnl_from_raw` (`runner.py:2743`) | raw dict | written to read `curRealisedPnl` from the flat payload, which never arrives → closing realized PnL lost (latent: C3 off live) |

Not affected: live liquidation uses Bybit `liqPrice` (`runner.py:1332`); the pair liq estimator is backtest-only. The REST fallback cannot compensate: `get_positions()` sends `settleCoin=USDT` without `symbol` (`rest_client.py:416`) and Bybit omits flat legs from that response — size-by-absence is correct, realized PnL is unrecoverable at startup.

## Design

1. **`leg_side` moves to `bybit_adapter`** — `packages/bybit_adapter/src/bybit_adapter/position_utils.py`, same contract: a non-empty `side` wins; else `positionIdx` `"1"`/`"2"` (int or str) → `Buy`/`Sell`; else `""`. Never raises. `event_saver.writers.position_writer` imports it from there; `event_saver.writers.__init__` keeps the re-export so `recorder.py:51` is untouched. gridbot already depends on `event-saver`, so this is responsibility placement (Bybit payload semantics), not a dependency fix.
2. **`on_position_message`** keys the cache by `leg_side(pos)` and **stores** the flat dict. Deleting the slot instead would suppress the 0023 paired snapshot (`orchestrator._on_position` returns while either slot is `None`), re-trigger REST on every tick while absent, and lose `curRealisedPnl` for C3. The raw payload is unchanged (`pos["side"]` stays `""`); only the cache key is normalised. Empty side with `positionIdx` 0 (one-way mode) stays skipped.
3. **`_fetch_one_account` REST fallback** uses the same mapping. Near-moot given the `settleCoin` scope, kept for consistency and a future symbol-scoped fetch.
4. **`None` and a size-0 dict are equivalent downstream.** Every consumer goes through `_build_position_state` (`runner.py:1324`), which returns `None` for size 0 before parsing any `""` numeric (`avgPrice`, `liqPrice`, `positionIM/MM`, `leverage`). Only `_evaluate_loss_breaker` reads the raw dict — the intended difference. Both-flat skips the risk calculations incl. `min_total_margin`, as with `None`.
5. **Rules:** replace the gridbot.md "Known hazard" with the fixed behaviour, distinguishing the 0064-gated size mirror from the ungated risk inputs, plus C3.

## Tests (PR-b, RED first)

1. **E2E close transition**, both legs, int and str `positionIdx`: seed both open → flat frame for one leg → orchestrator drain → runner: size 0, `_X_position_value == 0`, opposite leg preserved, a reduce-only intent on the flat leg rejected before the executor.
2. **C1**: legs size 1 @ entry 100, cap 150, other caps off → an open is blocked before the close (notional 200) and allowed after (100), through `_evaluate_safety_caps`, not a hand-fed notional.
3. **C3**: a flat payload whose `curRealisedPnl` crosses the threshold trips the breaker via the same path; later placements suppressed.
4. **0064**: dirty with REST baseline 0 → flat frame clears dirty/baseline/throttle/streak; dirty with a non-zero baseline → flat frame **held** (`runner.py:1524`, existing policy; a genuine later close leaves mixed state until the next eligible refresh — documented, not changed).
5. **Cache semantics**: both legs flat in one frame; repeated flat frames; reopen after flat; missing opposite slot → orchestrator guard still returns; no REST call when both slots are known.
6. **Contract**: empty side + `positionIdx` 0 skipped (rewrites `test_skips_empty_symbol_or_side`); non-empty side + `positionIdx` 0 stored; category filter kept; raw payload unchanged; blank numerics on the flat dict do not raise; cold startup where REST omits flat legs.

Ratio assertions: `gridcore/position.py:262` substitutes `0.0001` for a zero short margin, so closing the short leaves the long's ratio recomputed, not `∞`.

## Residuals (documented, not this feature)

- Accepting flat frames widens exposure to stale-frame ordering: the cache has no exchange-sequence check, and a populated flat slot suppresses the REST fallback, so a missed reopen would persist. Same class as today's non-zero-stale hazard; reconciliation work.
- C3 midnight reset can re-trip an unchanged loss (`safety_caps.py:143`) — issue #280.
- No testnet capture before merge; the Bybit doc example is the contract.
